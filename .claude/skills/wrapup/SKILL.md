# 收尾 = 轻收口(2026-08-12 Zihao 拍板)

审查外派 DeepSeek、发现只记账、10 秒自检后再 push。「今晚闭环才安心」是执念不是工程需要,账本不会丢。

## 1. 简化审查全部外派,Claude 只裁决

四角(复用 / 简化 / 效率 / 层级)全部派 `opencode run --agent worker`(DeepSeek · 并行 · 结论走 stdout),Claude 只做汇总裁决,**禁止再用订阅代理跑审查**。

- 当天改动若已在批次收口时扫过,收尾不重复扫。
- **simplify 的正确时机 = 批次收口边界**(与铁律#3 验证边界同拍):大批次(≥200 行或独立功能单元)收口时扫一次,小批次不扫;收尾只兜当天没扫过的尾巴。
- worker 完成、失败、遇阻或已不再需要后,立即终止本次启动的 `opencode` 进程树;再用进程列表确认 `opencode` 与它独占启动的本地模型均已退出。不要盲杀其他窗口共享的模型进程。

## 2. 发现只记账,不施工

审查发现全部写进交接账本,次日开工当首批 —— 修复照样派 DeepSeek worker 施工,Claude 只派单 + 验收,不是 Claude 亲自修。

- 当场只准动 ≤几行的零风险微修(注意别把代码改长,净增会撞棘轮闸)。
- 唯一例外 = 不修就不能 push、或推上去会污染生产;此时机械子步也照派 worker。

## 3. push 前 10 秒机械自检,再碰 push

别拿 5-6 分钟的钩子当第一道发现器,红一次多等一轮:

- 动过 src/static 前端源 → dist 重打包同提交
- 新文件 / 大净增 → 提交带 RATCHET-EXEMPT
- 动过用户可见文案 → `check_i18n --strict`

顺手清账,push 后盯 CI 到绿(见 `verification` skill):

```bash
git log --oneline origin/master..master     # 有没有本地没推的
git status                                  # 有没有该提交没提交的
```

## 4. **重写**(不是追加)STATE 顶部状态卡

`CLAUDE.md/STATE_PEARNLY.md` 分割线以上,保持 ≤30 行,永远最新:

- 当前 task
- 最后 commit
- 未 push 的 commit
- 剩余风险
- 下一步
- 在等 Zihao 什么

历史明细往分割线以下追加,不要顶上去。

## 5. 交付报告 → 清树

**拿 Zihao 的原话当尺子**,逐条对齐他要的东西:

- 做完的:一句话说清"他能看到什么变了"
- 没做完 / 跳过 / 还红的:直说,连原因
- 禁止把缩小后的范围报成"全部完成";禁止用"应该没问题"代替"验过了"
- 大白话,不堆术语,不复述过程

报告发完清树:临时脚本、散落产物清掉,别留在工作树。写完就停手,不要顺手开新任务。
