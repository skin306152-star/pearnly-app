# ERP 全商品收发存表

> 2026-08-27 对齐后的施工正本。发生冲突时，以本页和 `ERP-PRODUCT-BOUNDARY.md` 为准。

## 真实场景

个体老板上传采购或销售单据后，打开 `/erp#/stock-card`，应立即在一张固定格式的长表中看到所有商品的期初、逐笔入库、逐笔出库和每笔后的结存，不需要先看另一张汇总表，也不需要逐个点击商品。

这是高频核对报表。首屏必须让人直接回答三件事：哪张单据让库存变化、当时的移动加权平均成本是多少、该商品最后还剩多少。

## 固定展示

- 页面只保留一个“收发存报表”主视图，不设未入账页签或第二张汇总表。
- 报表严格复刻参考图的 13 列：日期、单据号、类型、说明，入库数量/单价/金额，出库数量/单价/金额，结存数量/单价/金额。
- 每个商品显示商品名称、编码和单位标题，标题下直接重复参考图的完整 13 列表格；该商品的期初与期间逐笔流水全部可见，末尾显示该商品合计，然后连续显示下一个商品。
- 所有商品默认展示，不设详情页、返回按钮、行点击、折叠、状态列、归并按钮、规则提示或搜索框。
- 参考图没有“未入账”按钮、页签或清单，因此网页与接口都不提供这套附加流程。
- 桌面端保留参考图三段式表头颜色；手机端每个商品表格在自身容器内横向滚动，页面本体不得横向溢出，也不把固定表改成信息卡片。
- 期初库存是用户另行明确要求保留的唯一报表附加能力；它作为每个商品的第一行流水参与计算，不给表格增加新列。

## 计算边界

- 每个商品按自己的 `key` 独立滚存，绝不跨商品合并数量、成本或金额。
- 保留既有移动加权平均算法和期初截至日语义：期初记录已吸收的流水不重复重放。
- 每组第一行是所选期间开始日的期初结转；期间内逐笔展示；组尾是该商品本期入库、出库及期末结存。
- 成本未知继续显示为空，不以 0 冒充；负库存继续显示负数，不取绝对值或隐藏。
- 尚未建立商品主档的名字轨仍按其名称独立成表，不在这张报表里提供额外处理按钮。

## 接口契约

- 前端主视图只请求一次 `GET /api/stockcard/report`，参数为 `workspace_client_id`、`date_from`、`date_to`。
- 返回 `groups`。每个 group 由 `product` 元数据、`rows`、`totals` 组成；`product` 只提供商品表标题和期初录入所需的 key、编码、名称、单位。
- 服务层应一次装载 movements/openings、一次批量取得商品名称和名字轨单位，再逐 key 纯计算；禁止每个商品重新查库的 N+1。
- 删除旧 UI 专用的 `/summary`、`/card`、`/excluded`、`/merge` 路由及前端调用。`services.stockcard.report.summary()` 与 `card()` 可继续作为管家内部工具使用，但不得再驱动网页的旧“汇总→单品详情”流程。

## 验收条件

- 桩数据至少包含：两个商品、一个名字轨、一个负库存商品、一个期初以及采购和销售流水。
- 桌面 1280×900 截图可连续看见多个商品表；每个商品都有独立期初、流水和合计，列数与顺序逐项匹配参考图。
- 手机 390×844 页面本体无横向溢出，各商品表格容器可横滚，商品标题仍清楚可辨。
- 四语切换后主表、商品标题和期初按钮全部刷新；没有“未入账”“归并”“状态”“点击商品查看明细”“返回商品列表”文案。
- E2E 明确断言旧的 `#stc-view-list`、`#stc-view-detail`、`#stc-back` 和可点击 `.stc-row[data-stc-key]` 不再存在。
