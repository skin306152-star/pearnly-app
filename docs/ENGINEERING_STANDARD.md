# Pearnly 工程标准

本页维护当前工程要求；历史整顿指标和模型工作流保留在 Git 历史中。任务范围遵循 `AGENTS.md`，检查命令以 [GATES](GATES.md) 为准，部署以 [Cloud Run 规范](deployment/CLOUD_RUN.md) 为准。

## 实现质量

- 复用现有业务边界、组件与错误约定；模块保持单一职责，不为降低行数压缩源码或制造空壳抽象。
- 遵循仓库的格式、类型、源码大小和棘轮检查。注释解释必要原因与约束，移除本次改动的调试残留，不吞掉真实错误。
- 金额精度、账套和租户隔离、幂等与权限在服务端保证；密钥和真实客户数据不提交到仓库。保持现有依赖锁定与安全检查。
- 变更公开接口、返回模型、前端资源或数据结构时同步相关契约和消费者；兼容策略按实际调用方决定。

## 产品与验证

- 用户可见状态诚实，失败/空结果不标为完成；覆盖加载、空、错误、正常状态和受影响的多语言、移动端交互。
- 按 [验证范围与证据](agent/VERIFICATION.md) 选择有意义的成功/失败路径，完成现有闸门要求；低风险变更不重复全套测试。
- 浏览器、真实数据库和外部 ERP 各证明自己的边界，不能互相代替。涉及测试写入只用隔离数据，不对生产余额或真实账套做试验。
- 当前 GitHub 常规 CI 已停用，保留本地检查与候选发布条件；不能把配置文件存在说成工作流已运行。

## 发布与交付

- 仅在任务包含发布时，按部署正本发布精确 SHA 的不可变镜像，回读 revision、digest、流量和正式域名。旧 SSH/systemd 流程不再适用。
- schema 初始化、调度器归属和持久文件遵循 Cloud Run 约束；回退要考虑数据库与文件兼容，不能仅换旧镜像。
- 本地检查、CI、部署、外部业务结果和用户确认分别记账。开发工具或文档任务完成不要求业务上线；真实功能未获用户确认不宣称用户验收通过。
- 提交描述真实改动和验证，不使用过期模型署名。长任务更新必要的本任务交接；实际发布更新部署账本，保护并行工作。
