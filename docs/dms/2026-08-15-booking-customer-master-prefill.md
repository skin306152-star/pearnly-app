# DMS 订车单客户主档回填修复

## 场景与对标

- JTBD：销售在 LINE 菜单 2 上传身份证后，系统先按菜单 1 的规则更新或建立客户主档；确认继续订车时，再按身份证号从 DMS 客户库检索并选中该客户，订车单只使用主档里的客户资料。
- 实用性：这是高频主链上的数据完整性缺陷。省/区/街道/邮编名称为空会让 DMS 页面和后续单据显示不完整，属于必须修复，不是功能扩张。
- 便利性：用户不应重复录入地址；客户查不到、身份证号与既有客户号不一致或主档地址不完整时，系统应停止建单并如实报错，不能创建半残单。
- 对标：遵循 DMS 原生订车页的 `txtcus` 搜索选择模式。原生选择客户后会一次回填 `cusval`、身份字段、地址主档 ID 和可见名称；Pearnly 的无头表单提交必须保持同一契约。

## 生产证据

2026-08-15 账号 `korndms` 的客户 `119` 主档具有完整地址名称，但订车单 `BK000002608000020` 只有 `provincesval/districtsval/subdistrictsval/zipcodesval`，对应 `txt*` 可见名称均为空。原因是建单使用 OCR 会话草稿，其中只有地址 ID；没有在建单前重新读取客户主档。

## 修复契约

1. 建单前按身份证号调用 DMS 客户搜索。
2. 搜索结果必须与待建单的 `customer_id` 一致。
3. 从搜索结果的客户主档重建订车单客户快照，包括四级地址 ID 与名称。
4. 主档缺失关键地址或发生串号时 fail closed，不提交订车单。
5. 自动化测试锁定“先查主档、后解析车型和提交”的调用顺序，以及四项可见地址名称。
