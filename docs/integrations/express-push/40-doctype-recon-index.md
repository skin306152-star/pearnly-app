## 四、P2-B 施工建议顺序

按四份详报各自的难度评级与风险面综合排(**这一节是索引层的编排建议,不属于任一份详报的原结论**):

1. **手工总账凭证(43)** —— 难度低–中,必写表仅 2 张,无取号回写、无子账联动、无跨单副作用;
   借贷平衡一条断言就能兜住。先做它同时把「金样本 diff → 定案 GLBAL 要不要写」这个悬案解掉,
   后面三类都吃这个结论。
2. **库存调整之 OU / ZZ 子类(44)** —— 生产账套有 193 张真样本可逐字段对标,单方向、单头只填 `ACCNUMDR`、
   GL 恒 2 行。先把 `ISPERPETUA` 闸和 `MLOTNUM` 批次链闸建起来,再放 JU/TK/CA。
3. **客户收款单(41)** —— 难度中,第一次引入「反写别人的单头」,但只反写发票一张表,回滚集可控;
   第一版按详报建议**拒收 `FLGVAT='2'`(收款基础销项税)场景**转人工。
4. **供应商付款单(42)** —— 难度高,放最后:跨单反写 + 三张缓存表(APBAL 双年桶 / APMAS / GLBAL)
   + 预扣税法定凭证(ภ.ง.ด.3/53,算错是真金白银的税务风险)。第一版范围按详报收窄到
   「单一供应商 + 单一银行·支票 + 全额或部分结清赊购票 + 可选预扣」,退货冲抵 / 预付冲抵 / 汇兑损益 /
   付款时认列进项税四类先 escalate 转人工。

三条贯穿全批的硬约束(四份详报各自独立踩到,不是巧合):

- **软删行必须过滤,且不能拿来判「号已占用」**。收款单软删后子表留活行、付款单单号会被复用、
  手工凭证改单 = 软删旧行 + 追加新行。命中已知血泪 `dbf-soft-deleted-rows-fake-success`。
- **科目一律从目标账套配置读,零硬编码**。AR 走 `ARMAS.ACCNUM`、AP 走 `APMAS.ACCNUM`、
  收付渠道走 ISRUN `ZR`/`ZP`、预扣走 `istab` TABTYP=55、存货走 `ISACC`,每家账套都不同。
- **写后回读闸的源码依据 = 各详报第 4 节的断言表**,含实测「跑过多少张真单、违反几例」,
  抄的时候把已知会假红的例外一并抄走(如 AP 的 A5/A12,库存的单头 `TRNVAL` 漂移)。
