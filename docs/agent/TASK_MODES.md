# 任务范围与产品设计

以当前对话为准；“继续”续接本任务，不自动切回历史重构主线。先做有依据且已授权的部分，只对影响结果的关键歧义询问。

| 当前请求 | 处理范围 |
| --- | --- |
| 查日志、查原因 | 先只读定位因果链，使用生产诊断技能 |
| 修复、实现 | 沿现有模块实施并验证影响路径，必要工作持续完成 |
| 测一下、验收 | 按所请求的消费者与场景验证，分别记录证据和缺口 |
| 方案、调研、对比 | 核对现有产品和代码，给具体选择、影响和验收标准 |
| 发布、上线 | 使用发布技能与当前部署正本 |
| 收尾、交接 | 保存本任务状态和证据，清理本任务资源 |

## 需要产品设计时

先明确谁在什么情境下完成什么工作，再检查已有模块和真实输入。优先复用现有主数据、去重、重试和集成路径，给用户简单的角色流程。

只有在需要比较产品取舍时才使用市场对标、RICE/Kano 或独立设计文档；已明确的小修不重复 discovery。技术选择由执行者给结论和依据。

若不同解释会改变账务含义、账套归属、权限或真实资金处理，明确歧义再进行依赖它的修改；这不要求每次触及相关文件都重新审批。

重构保持业务行为和调用契约，按实际风险验证。接口兼容层是否需要保留取决于调用方与迁移策略，不按固定行数强制外派或要求每个新文件单独配测试。
