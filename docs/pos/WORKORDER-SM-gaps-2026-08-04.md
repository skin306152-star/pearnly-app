# 工单 · SM 语料评审暴露的 POS 缺口批次(2026-08-04 立案 · Zihao 拍板全补)

> 依据:`桌面/Pearnly-产品语料测试数据/SM-照片语料(题面A+答案BC-5月)` 全量评审
> (104 张原料照:60 销项 / 11 进项 / 19 支付凭证 + ภ.พ.30 正本 + 既有工单分类)。
> 客户画像:**Sister Makeup(曼谷美妆专门店)= Pearnly「POS+代账一体」ICP** ——
> VAT 注册小微零售,月销 ~86 万铢,Ocha POS + EDC + 大量银行转账,纸质单据手写编号
> 交代账事务所,销项靠倒推。**所有方案按客户类型做通用,不做 SM 特例。**

## G1 · 简式税票(ใบกำกับภาษีอย่างย่อ / ABB)合规化 —— P0

现状(查实):`services/pos/numbering.py` 有 `abbrev_tax_invoice: "ABB"` 单号类型,但全仓
搜不到「ใบกำกับภาษีอย่างย่อ」抬头字样;`services/pos/receipt_pdf.py` 只组装
店名/地址/税号/票号/VAT 额。对 VAT 注册客户,小票就是税务文件。

要补(按泰国税法 ABB 要件):
- 票面印泰文法定抬头「ใบกำกับภาษีอย่างย่อ」(可并列英文 Receipt / Tax Invoice (ABB))
- 「ราคารวมภาษีมูลค่าเพิ่มแล้ว」(价已含 VAT)声明(price_includes_vat 时)
- 连续票号(已有 numbering)+ 出票日期时间 + 卖方名/税号(已有)
- 收银员名上票(SM 现票有 Served By;库里有 cashier 数据,receipt_pdf 没带)
- 开关:**按账套 VAT 登记状态**出 ABB 版式;非 VAT 户出普通收据版式(通用兼容)
- 深水区先立案不动手:机打 ABB 严格说需向税务局登记收银机(票上 Register No.),
  接真客户时按需办,票面先预留 Register No. 字段位

## G2 · 收银台 → 全式税票(ใบกำกับภาษีเต็มรูป)通路 —— P1

场景:客单 ฿2,728/13 件的买家(化妆师/公司采购)要全式税票抵扣。SM 现在手写 SW 号
对台账补开。对标 Loyverse/StoreHub 泰国版标配。

要补:凭小票号召回交易 → 填买方抬头/税号 → 生成全式税票(主站已有开票模块,
接的是通路:pos_sales ↔ 销售发票模块的转换入口,买方档可存回客户管理)。
入口两处:收银台「补开税票」+ 主站交易明细行内动作。

## G3 · 销项月度汇总直通代账 —— P1(胜负手)

场景:SM 的会计靠「银行流水+EDC+Ocha 小票」倒推销项。Pearnly 的 POS 数据在库,
`services/pos/sales_log.py` 导出已有 subtotal/discount_total/vat_amount 拆列(查实)。

要补:按月一键出「销项汇总包」(供事务所/直推 ภ.พ.30 管线):日汇总 + 支付方式拆分 +
VAT 拆列 + ABB 票号区间;与月结 Agent 的销项管线对接(它正缺 POS 直采销项,见
vat-filing-sales-summary-gap 记忆)。

## G4 · 小票增强(随 G1 一批做)—— P2

- 「扫码领电子小票 / 申请全式税票」二维码上票(把手写编号的纸质流消掉,给 G2 引流)
- 支付方式/找零已有;核对票面是否印支付方式与找零

## 明确不做(评审否决,别被语料带偏)

- Time in/Time out 服务时长、预约/试妆记录(超 POS 边界,多数零售客户是噪音)
- 转账凭证强制上传(先观察,不加摩擦)

## 验收口径

四语齐 · 真浏览器 E2E + 截图(票面渲染逐要件断言)· 高敏(钱/税务文件)当场验 ·
新客户类型开关有单测 · 对照 SM 真票逐字段核。
