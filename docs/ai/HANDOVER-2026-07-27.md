## 六、这一轮学到的教训

1. **假绿第四型:两仓各照各的镜子。** P2-B 云端产物喂进桥端 validate,**四类里只有 2 类过**,而两侧的单测都是绿的。根治不是「再加一个测试」,是**把交接物落到磁盘上,一份,两仓共用**,再配三层闸(fixture 新鲜度 / 云端镜像 / 真桥 validate)。缺任何一层就退回假绿。
   —— 而这道镜像闸**今天就抓到了第一条真漂移**(§3.1),证明它是活的。

2. **闸在但扫不到,长期报绿。** 本轮抓到三例:① 老链路跨仓契约闸把桥仓路径写死 D 盘,搬家后一直静默 skip;② 隔离闸只认 `src.` 一种拼法,`companion.x` 整条穿过去;③ py38 扫描器与写打开单口闸配了反证,隔离闸没配 —— **清单式闸没有反证测试,长期报绿无法区分「代码干净」与「闸根本没看」**。三条都补了「喂已知有毒样本」的反证。

3. **验证脚本自己就是缺陷源。** 靶场那次「HP/RR 写路失败」查下来是**验证脚本的锅**:`payload()` 完全没带 `items` / `items_status`,`purchase_adapter` 对缺失取默认 `"empty"`,写路整段跳过明细。同一份报告里还有两处断言对不上真列名(`YOUREF` vs `REFNUM`、`RECTYP` 期望值写错)。
   **教训**:验证脚本没跟真表核对,就能拿空载荷跑绿。已加负向断言把「表头模式」的输出形状钉死。

4. **考卷绕开唯一会炸的地方,就等于没考。** 见 §3.8。串两步那题挑了个参数选填的工具,成本闸那几题靠注入现成 gate —— 两条断掉的能力被验成绿。**出题时要专门挑「必填 / 会累加 / 会炸」的那条路。**

5. **进程在跑的是提交前的旧码。** 7860 上 PID 起于 06:59,批次提交在 13:48,最初问「今天先干哪个」拿到 `out_of_scope` 拒答,差点误报成路由缺陷。**验收前先确认进程起动时间晚于提交时间。**

6. **`RATCHET-EXEMPT` 必须写在 commit message 里,而共享工作树禁 amend** → 只能单开一笔空 chore 提交声明豁免(本轮开了 11 笔:`852b6cff` `0a5db2ba` `079f0e80` `52fc2e42` `3c9b8451` `c058de49` `65580b38` `e178f1d6` `6ff89cfb` `7cd3bae6` `40cf63bb`)。这是现有工具链的必然产物,不是懒。
   **另**:本轮有代理为改 commit message 而 amend(PowerShell here-string `@'…'@` 喂 Git Bash,`@` 被当字面量,标题被污染成 `@ fix(...)`)—— 污染痕迹现在还留在 git log 里:app 5 笔(`2801793c` `c2b048e6` `d6158a49` `873ada59` `77acfb50`)+ companion 1 笔(`5ac14f5`)。**多行提交信息一律 `git commit -F <文件>`。**

7. **CSS 注释里写 `*/` 会提前闭合注释**,后面整段变成非法选择器被浏览器整条丢弃(`ai-dashboard.css` 的 `.kb-tools` 就这么没的)。prettier 还会把它重排成更乱的样子。

8. **E2E 断言点完立刻取 computed 值会撞过渡中途值**(120ms transition)—— 改 `expect.poll`。移动端量 `min-height` 必须开 `hasTouch+isMobile`(规则挂在 `@media (pointer: coarse)`),否则量到桌面值是**脚本假红不是产品缺陷**。

9. **「文档漂移」这次是反方向的:实际比文档更绿。** 两条被记成「没做」的(IN-0a/b、建档税号警示)其实当天或次日就做完了,只是 STATE/记忆从未回填。**盘点时别只信文档说「没做」,要去代码里核。**

10. **产品哲学纠偏(Zihao 07-27,已进长期记忆)**:红线不是「模型能不能算」,是「**错了能不能被发现、能不能改**」。管家 discovery 曾因「对话框没有上传口」砍掉三项能力 —— 把当前缺失当成固定约束,正确反应是**把上传口建起来**(已建,见 §一.I)。见记忆 `assist-not-replace-loosen-the-model` / `steward-universal-intake-is-the-product`。
