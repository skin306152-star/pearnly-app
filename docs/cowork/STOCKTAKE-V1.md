# Cowork 库存盘点：扫描实物与逐笔累计

## 入口与操作

网页入口是 `/cowork#/stocktake`，位于 Cowork「对账中心」下面。网页只包含列表、新建弹窗和详情。新建时上传统一 `.xlsx` 模板，校验通过后立即开始；不提供覆盖账面数据的接口。导入失败整批不落库。

LINE 在现有 Cowork 菜单卡「上传单据到 ERP」之后增加「库存盘点」跳转按钮。沿用 `LINE_COWORK_LIFF_ID`（以及现有 `LINE_LIFF_ID` 回落）和已绑定的 Cowork 成员身份；无需新增 LIFF 应用。菜单 URI 为既有 LIFF ID 加 `flow=cowork-stocktake&draft=list`，既有 `/home`、`/login` 主重定向选择手机盘点壳。LINE 底部 Rich Menu 第一格为上传单据，第二格为库存盘点；菜单卡与底部菜单分别使用单据发送和盘点清单图标。2026-09-06 已发布并回读默认菜单 `richmenu-0aa42f054b8a47a8d1d9e7db9012e8be`，两个点击区域及上传图片字节一致；旧默认 `richmenu-c25aa3ffb5478c93253fcb42299ade25` 保留用于回退。四语 Flex 卡通过 LINE validate API，不发送测试消息。

手机选择公司和盘点任务后自动启动相机。先扫实物条形码或 QR，精确匹配后自动显示商品；选择或输入实际仓库／库位，输入本次数量并提交，再自动扫描下一件。手动输入条码、QR 编号或商品编号可替代相机。每次扫码重新带出该商品导入的账面仓库／库位，不沿用上一笔；账面留空时输入框留空。实际位置可修改，修改历史记录时加载该记录的位置。候选来自导入位置与已有盘点位置。每次提交新增一笔记录，同商品各位置的有效记录累计为实盘总数；记录可单独修改或撤销。

QR 内容是公司的内部商品编号，按解码后的完整字符串匹配，不解析成网址动作，也不上传二维码图片。商品匹配只查本次导入的数据，不访问 POS 商品或 ERP 库存。网页复用 Cowork 壳，手机复用 Cowork LINE 身份、词典与公共设计令牌。

相机复用 `PearnlyScanCamera` 的媒体与条码引擎，同一视频流另用已内置 WASM 解码 QR。本次修正共享 WASM 初始化兼容：上游初始化返回 void 时也可加载；不改变 POS 计数和商品逻辑。手机明确加载带版本的 scan.js，使共享 WASM 资源取得缓存指纹。相机权限拒绝后保留手输。

## Excel 约定

一个工作表、一行一个商品，账面数量是该商品合计。默认泰语七列表头如下，最后两列可留空；也接受只保留前五列的模板。

| 默认泰语表头 | 英文标识 | 内容 | 必填 |
| --- | --- | --- | --- |
| รหัสสินค้า | product_code | 商品编号，Excel 文本格式，保留前导零 | 是 |
| ชื่อสินค้า | product_name | 商品名称 | 是 |
| บาร์โค้ด / รหัส QR | barcode | 条形码或 QR 内部编号，Excel 文本格式 | 否 |
| หน่วย | unit | 单位 | 是 |
| จำนวนตามบัญชี | book_qty | 商品账面总数，可负数，最多 6 位小数 | 是 |
| คลังสินค้าเริ่มต้น (ไม่บังคับ) | warehouse | 可选默认仓库 | 否 |
| ตำแหน่งเริ่มต้น (ไม่บังคับ) | location | 可选默认库位 | 否 |

保留旧七列英文／泰语模板顺序的导入兼容，但新任务仍要求一行一个商品。重复商品编号、不同商品共享同一条码／QR，或一个商品的编号与另一个商品的条码冲突都会整批拒绝。匹配保留大小写与前导零，不模糊归一化身份。

单次最大 5 MB、10,000 行，解压总量上限 40 MB；拒绝公式、无效数量和数字格式编号。实盘必须大于等于 0，最多 6 位小数。没有有效盘点记录为 NULL，输入 0 则为已盘零数量；撤销全部记录后恢复未盘状态。

导出固定泰语两页：`สรุปผลตรวจนับ` 每商品一行列出账面、累计实盘、差异与结果，以及账面仓库／实际仓库／仓库对比、账面位置／实际位置／位置对比；多个实际位置换行列出。所有有效记录均与账面值相同才标为一致，未盘点与账面未提供分别标记；`รายละเอียดการนับ` 列出每笔实际仓库／库位、对应账面仓库／库位及各自对比、数量、盘点人及时间、是否计入累计、最后修改人及时间。撤销记录保留并标明不计入总数。未盘点的实盘与差异为空；导出不随页面语言改变。文本显式作为字符串防公式注入，超过 Excel 15 位有效数字的数量以文本保留精度，时间标记为 UTC。

## 权限、并发与数据边界

沿用 Cowork 现有权限：`recon.view` 查看，`recon.create` 新建、盘点与结束，`recon.export` 导出。公司权限沿用现有成员分配范围，所有业务查询绑定 `tenant_id + workspace_client_id`；缺少公司头拒绝。LINE 每次 API 调用重新检查活跃绑定与成员权限，盘点令牌不会用于其他业务 API。

任务与商品快照保存在 `cowork_stocktakes`、`cowork_stocktake_items`；新逐笔记录与审计保存在 `cowork_stocktake_entries`、`cowork_stocktake_entry_events`，使用组合外键和租户／账套 RLS。迁移 0124 只添加结构；旧任务保留 legacy 模式与 `cowork_stocktake_counts`，继续使用旧计数方式，不把历史合计伪造成位置明细。账面数据不会流入库存更新或 ERP 推送逻辑。

新建请求使用客户端 UUID 和原文件摘要保证重试不重复创建，不能用同一请求 ID 替换快照。每笔新增／修改使用操作 UUID、规范化请求内容与操作者校验重试；同 ID 同请求只记一次，同 ID 不同内容返回冲突。不同 UUID 即使数量相同也是独立盘点记录。修改另检查版本；每次修改保留前后状态、版本、操作者和 UTC 时间。缓存中的旧计数接口不能覆盖新任务累计值。

保存与结束均锁定盘点任务行，避免结束后继续写入。结束动作幂等，保留结束人和时间。结束允许保留未盘点项，弹窗会显示未盘点数量并明确这些项不会变成 0。
