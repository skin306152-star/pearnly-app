# 验证范围与证据

依据当前改动选检查；既有 pre-push、CI 和发布候选的强制条件仍有效。检查结果绑定代码版本与环境，没有新改动、失败或新证据就复用，不在开工、收尾、提交前手动重复全套。

## 选择范围

- 文档/指令：检查引用、格式、结构与冲突；不跑业务 E2E 或重发容器。钩子脚本改动另做语法和实际调用验证。
- 后端业务：覆盖受影响的成功、失败和权限路径。SQL 变化在隔离的真实数据库验证；破坏性测试遵循 `tests/integration/README.md` 的 disposable DB 哨兵。
- async 路由调用同步阻塞库时通过线程等现有异步边界隔离，用真实事件循环和 async HTTP 调用验证；仅同步 mock 通过不算异步链路通过。
- UI：真实浏览器走受影响入口，保存截图，核对可见性/样式与必要的桌面、手机和语言切换。扫码、焦点或键盘行为用真实按键事件，不能仅靠 `fill()`。
- 登录、租户、计费、推送、POS 收款、迁移：覆盖影响到的隔离、幂等、失败与恢复条件；只使用隔离测试数据，不能动真实付费用户余额。
- 发布：按部署正本验证候选和正式环境身份；外部 ERP 通过 report/listing/detail 回查，不以 HTTP 200 或内部状态代替。

命令和触发条件见 [GATES](../GATES.md)。检查失败后重跑失败项及受修复影响的项；不能用删断言、全局忽略或绕过钩子过闸。

## 浏览器与外部系统证据

- 每个断言要能区分目标路径与相邻路径；调用了错误处理分支也会通过的信号不够。
- 元素唯一定位；按位置选择必须说明对象，沿用 `SELECTOR-INDEX-OK` 的现有检查。
- 文案期望从实际词典/产品契约取得，不注入自带词典证明自己正确。针对可能失败的输入验证，避免只用理想静态样本。
- 缓存、去重和扣费复验使用独立测试输入/标识，确认请求确实经过目标代码。外部写入重试前先查结果，避免重复入账。
- 证据记录版本、环境、场景、预期、实际和未覆盖部分。需要观察部署结果时用 Cloud Run 的 revision/digest/流量与正式域名回读。

## 交付表述

实现、本地检查、CI、部署、外部业务完成和用户验收分别说明。用户未确认就不记 `USER_ACCEPTED`；任务仅要求文档或代码修改时，按该范围说明已完成，不自动扩展成上线任务。
