# ERP 产品边界

> 2026-08-27 产品决定。发生冲突时以本页为准。

## 两个独立产品

- `/cowork`：会计事务所自由注册，管理事务所自己的客户与做账流程。
- `/erp`：个体老板经 Earn 邀请进入，管理自己的采购、销售、商品库存与第三方 ERP 推送。
- 两边可共享登录、OCR、商品、采购、销售和 ERP adapter 底座，但租户、单据、余额与业务状态各自隔离。

## 禁止的关系

- Earn 邀请 ERP 商户时不选择事务所。
- ERP 商户不与 Cowork 租户建立 engagement。
- ERP 确认单据不向 Cowork 创建副本、发件箱或投递任务。
- Cowork 不提供 ERP 商户提交件接收页。
- 第三方 ERP 推送状态继续只认 `erp_push_logs`，不得新建并行状态源。

## ERP 商品口径

- 商品页不再先展示汇总、再点击进入单品卡；同一份收发存长报表按商品连续排列，直接展示所有商品的逐笔 Stock Card。
- 商品之间独立滚存数量、移动加权平均成本和结存金额，禁止把不同商品混算；交互与接口细则见 `STOCK-CARD-ALL-PRODUCTS.md`。
- 保留期初库存；采购、销售及明确的调整形成后续流水。
- 单据进入正式数据前必须给用户预览、编辑、确认或丢弃。
- LINE 不猜采购/销售，也不猜库存/服务；由用户明确选择，混合单据逐行选择。

## 历史迁移

`0104_accounting_engagements` 与 `0105_client_submissions` 已进入 Alembic 迁移链，只作为部署历史保留；运行时不导入、不建表、不读写、不启动 worker。生产库若要物理删除历史表，必须单独列出目标并在备份后执行，不与功能代码清理混做。
