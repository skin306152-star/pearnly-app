# WeKan / COWORK integration — deployed 2026-09-12

## Result and scope

Production entry: **https://pearnly.com/cowork** → 工作协作 /
การทำงานร่วมกัน → **https://work.pearnly.com**.

All COWORK users have the entry. There is no firm allowlist, per-firm activation,
or first-owner configuration. Pearnly remains the login and ordinary employee
account authority; WeKan retains native site and board permissions. A WeKan
role never grants a Pearnly owner/platform-admin role. Existing Pearnly users can
be invited without resetting their passwords or changing their COWORK membership.
New WeKan-issued accounts use Pearnly passwords and ordinary employee roles.

The user authorized implementation and deployment. Cloudflare sign-in succeeded
in the requested external Chrome; the previous phone-confirmation blocker is
resolved. No further Google verification code is needed for this deployment.

## Architecture and hosting

- `/work` creates browser-bound one-use handoff tickets. The gateway stores an
  encrypted HttpOnly opaque parent-session cookie; no Pearnly JWT is exposed to
  WeKan JavaScript. Every HTTP/file request and WebSocket upgrade validates the
  parent; live WebSockets revalidate every five seconds.
- Native login/resume and HTTP tokens must match the gateway identity. Public
  native signup and independent password changes are closed. Native permissions
  govern invitations, issuance, boards and cards; Pearnly tenant/account
  revocation remains authoritative for Pearnly access.
- New bridge tables use RLS, expiring single-use tickets, immutable user links,
  idempotent employee requests and parent-session revocation.
- GCP project `pearnly`, zone `asia-southeast1-b`, VM `pearnly-work`, e2-medium /
  4 GiB. Static IPv4 `136.85.65.80`, DNS-only `work.pearnly.com` A record, valid
  Caddy TLS. Existing root/www Worker routes and mail DNS remain intact.
- Retained 30 GiB `pearnly-work-data` disk, UUID mount `/srv/pearnly-work`.
  Docker data and all native volumes reside there. MongoDB uses authentication;
  application DB credentials have only `readWrite` on `wekan`. Only Caddy 80/443
  is public, gateway 8096 is loopback, WeKan/MongoDB ports are private, SSH is IAP.
- Dedicated VM service account reads only its runtime secret and image registry.
  `pearnly-work-env:2` contains the final image; Web/Worker env secrets are v3,
  preserving previous fields and appending only the bridge URL/secret.
- `/_pearnly/health` verifies native MongoDB access as well as gateway reachability.
